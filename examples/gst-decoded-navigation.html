01

Brief & spec

Let readers see where they are, jump between chapters, and return to the same chapter reliably on desktop and mobile.

People in the frame

  • First-time readers moving through the course sequentially
  • Returning readers revisiting a specific GST topic

Working constraints

  • Preserve the existing React, TypeScript, Vite, GSAP, and Framer Motion stack
  • Do not obscure chapter content or compete with the storytelling
  • Respect keyboard navigation and reduced-motion preferences

02

Architecture

Keep chapterMeta as the source of truth, add a small navigation controller that reconciles viewport state with the URL, and let desktop and mobile views consume the same controller rather than duplicating behavior.

System components

Chapter navigation controller✓ Reviewed

Responsibility
Resolve initial deep links, update the active chapter, and prevent URL-scroll feedback loops.

Interfaces
chapterMeta, useChapterInView, history.replaceState, scrollIntoView

Failure boundary
An invalid chapter parameter falls back to the first chapter without breaking render.

Desktop chapter rail○ Pending

Responsibility
Show location, chapter titles, completion context, and direct navigation without covering course content.

Mobile chapter sheet○ Pending

Responsibility
Offer the same chapter map in a touch-friendly progressive disclosure pattern.

Architecture decisions

  • Use the existing chapter metadata instead of introducing a second navigation registry.
  • Use replaceState during passive scrolling and pushState only for explicit chapter jumps.
  • Keep motion decorative; navigation state must remain correct when motion is disabled.

Critical review

Product criticA large always-open mobile table of contents would interrupt the course more than it helps.✓ Accepted

Disposition
Use a compact current-chapter trigger and reveal the full list only on demand.

Architecture criticTwo independent active-chapter states would drift during smooth scrolling and browser navigation.✓ Accepted

Disposition

Decision record

Rationale
